# 設計筆記：踩過才知道的事

[English](DESIGN-NOTES.md)

每一條都是實際發生過、量過的，不是推論。細節在程式碼註解裡（搜尋 `⚠️ 為什麼`）。

## 串流與畫面

### 框要在伺服器端燒進畫面
前端拿 WebRTC 畫面、另一條通道拿結果，再用時間戳對齊。量過，對不起來：go2rtc 對每個 consumer 開獨立 session，
RTP timestamp 各自起算，偏移還會抖 200ms（[實測](findings/2026-08-28-sync-verification.md)）。
在畫面裡嵌幀標記可以對齊，但瀏覽器端每幀解碼標記很貴，而且依賴 MSE；最後選擇 runner 用 nvdsosd 把框燒進
`<cam>_marked`，前端零工作（[決策](findings/2026-09-04-overlay-decision.md)）。

### 多個前端一起卡，不一定是頻寬
go2rtc 會把所有網卡的 IP 都當 ICE candidate 公告；瀏覽器先試到連不通的那個，要等逾時才換。
只公告一個瀏覽器連得到的 IP（`WEBRTC_IP`）就好了。

### 相機會定期斷線重連，重連後頭幾幀是殘影
解碼器缺參考幀時會停在舊畫面加馬賽克，模型照樣判，曾經一天的 NG 全落在重連時間點。
worker 偵測到某台相機一段時間沒幀，恢復後先停判幾秒、清掉站別的跨幀狀態。

## 推論

### nvinferserver 的 batch 會照 engine 的上限配記憶體
engine 匯出時 max batch 開很大，Triton 每個實例就照那個尺寸配，幾顆模型就能把 48GB 的 MIG 切片吃光。
max batch 要照實際相機數匯出，runner 啟動時比對「這條線的相機數 ≤ engine 的 max batch」，並有 GPU 記憶體看門狗。

### seg 模型的 prototypes 搬運比推論還貴
每幀 32×160×160 的 prototypes 從 GPU 搬回主機再走 gRPC，7 路就是 463 MB/s，Triton 的 CPU 七成花在這裡。
把 mask 合成放進 ONNX（輸出已裁好的 mask），搬運量降六成（`edgevision/training/seg_fuse.py`）。
代價是 max_det 一定要小：每個偵測一張 160×160，300 列就是 30 MB/幀。

### TensorRT engine 綁 GPU 架構與 TensorRT 版本
engine 一律用「Triton 映像自帶的 trtexec」建，別在訓練映像裡建；模型庫按 GPU 架構分目錄（`_triton/sm89`、`sm120`）。

## 設定與資料

### 設定是宣告式的，runner 要回報它實際套用的版本
「我改了設定」和「線上已經是這個設定」是兩件事。每條線有 desired / reported 兩個版本，`/healthz` 一眼看出誰沒跟上。

### 模型自己的屬性只能有一個來源
類別名以前在線路設定裡存一份，靠人手抄；模型換版後那份就過期了，runner 照舊名字翻新模型的類別編號，
而且沒有任何錯誤。現在線路設定不存類別，讀取時從 Registry 附上；站別引用的每個類別名，runner 啟動前逐台比對。

### NG 是判定，不是框
「A 之後 10 秒內沒看到 B」這種規則，NG 那一幀可能一個框都沒有。以前「有框才落地」，這種 NG 就查不到、影片也掛不上去。
發布、落地、錄影一律以 Verdict 為準。

### 閘門只能有一道
錄影層曾經自己加冷卻，結果是「資料庫有 NG、卻沒有影片」，而且分不出是設計還是故障。
去重屬於判定層（連續幀、冷卻都在站別裡），錄影層照單全收，兩邊一對一，不一致就一定是 bug。

### 數值一律參數化
一輪抽幾張、抽查比例、門檻、幀數，程式只給預設值，實際值放設定，前端只讀後端回的設定。

## 營運

### 容器 log 一定要設上限
沒設輪替的容器 log 曾經長到幾百 GB、把整台測試機弄掛。所有服務都設 `max-size` / `max-file`。

### 磁碟壓力會讓 K8s 趕走 Pod，runner 要能自己爬起來
節點硬碟滿 → go2rtc、redis 被驅逐 → runner 同時斷線，恢復後也接不回去，停了一天半沒有推論。
runner 加了看門狗：串流全斷或依賴掛掉一段時間就自我重啟，不靠人。

### 不做 API gateway，用 Ingress 依路徑分流
自寫 gateway 很容易長成第二個後端。路徑前綴對到服務，認證在各服務驗 JWT。

### 映像要真的存在才部署
訓練映像不是每個 commit 都重建，標籤預設跟主映像同一個時，曾經指向不存在的映像，直到第一次送訓練才發現。
`apply.sh` 先查每個映像標籤存在才套用。
