# 實測記錄：影格身分標記（frame marker）

> 日期：2026-08-28
> 背景：時間戳方案經實測不可行（見 `2026-08-28-sync-verification.md`）

---

## 結論

**方案成立，可作為同步的主方案。**

```
✅ H.264 壓縮往返 100% 正確（0.3 Mbps 起，含 4 Mbps 高碼率）
✅ 極端條件（全雜訊背景 + ultrafast + 0.2Mbps）仍 100% 正確解碼
✅ 無標記畫面正確拒絕（純雜訊、純灰階皆回 None）
✅ 編碼成本 15.8 ms/幀 → 20fps 佔用 32% 一個 core
```

---

## 原理

把 frame id 以黑白方格編碼，畫在影格左上角。

```
影像本身攜帶身分 → 不論中間經過幾層轉發或重新編碼，
                   id 都跟著像素一起走
```

這解決了時間戳方案的根本問題：RTP timestamp 由各條連線各自維護，
而畫面內容是共通的。

## 版面設計

| 欄位 | 位元 | 用途 |
|---|---|---|
| SYNC | 4 | 固定 `1010` 樣式 |
| ID | 20 | frame id（約 100 萬，20fps 可跑 14 小時不重複） |
| CRC | 8 | CRC-8（多項式 0x07） |
| **合計** | **32** | |

尺寸：**324 × 14 px**，佔 720p 畫面 **0.49%**。

### SYNC 樣式的兩個作用

```
① 存在性檢查 —— 沒有標記的畫面不會誤判出 id
② 自適應閾值 —— 用 1010 的黑白值當參考，動態決定判定門檻
                 壓縮會壓縮動態範圍，寫死 127.5 在低碼率下會判錯
```

### 為何 CRC 從 4 bit 加大到 8 bit

初版用 CRC-4，16 種值的隨機碰撞率 1/16，在高位元錯誤率下擋不住。
CRC-8 降到 1/256，配合 SYNC 檢查後誤讀機率可忽略。

> **誤讀比漏讀危險**：漏讀只是這一幀沒框，誤讀會把框畫到錯的幀上。

## 壓縮測試

### 標準條件（一般畫面）

| 碼率 | 結果 |
|---|---|
| 0.3 Mbps | 60/60 |
| 0.5 Mbps | 60/60 |
| 1 Mbps | 60/60 |
| 2 Mbps | 60/60 |
| 4 Mbps | 60/60 |
| 8 Mbps | 60/60 |

### 極端條件（全雜訊背景，最難壓縮）

| 條件 | 解出 id | 無效 id |
|---|---|---|
| 0.2 Mbps ultrafast | 40/40 | **0** |
| 0.5 Mbps ultrafast | 40/40 | **0** |
| 1 Mbps ultrafast | 40/40 | **0** |
| 2 Mbps veryfast | 40/40 | **0** |

> 初版測試曾報告「誤讀」，經診斷是**測試腳本的假設錯誤** ——
> 腳本假設「解碼順序 = 編碼順序」，但編碼器在低碼率下會重複或
> 丟棄影格。實際上**每一次解出的 id 都是有效值，標記從未讀錯**。
>
> 這反而證明了方案的價值：標記能忠實反映「這一幀到底是哪一幀」，
> 即使編碼器動了手腳 —— 這是時間戳方案抓不到的。

## 已知限制

### 影像縮放會使標記失效

```
縮放 0.75x → 0/40
縮放 0.50x → 0/40
```

縮放的插值會糊掉方格邊界。

**因應**：標記必須在**最終輸出解析度**上打，且下游不可再縮放。
若前端需要縮放顯示，用 CSS 縮放 `<video>`（不影響 `drawImage` 取到的原始像素）。

### 格子尺寸

實測 4px、6px、10px 在 2 Mbps 下皆 100% 正確。
採用 10px 保留餘裕 —— 標記只佔 0.49% 畫面，不值得為此冒險。

## 效能

```
單路 720p H.264 編碼（libx264 veryfast + zerolatency）
  15.8 ms/幀
  20 fps → 32% 一個 core
  12 核機器理論上限約 37 路
```

> 相比 passthrough 的零成本，這是導入標記的主要代價。
> 但換得完美同步，且 720p 的編碼成本可接受。

## 前端解碼

```javascript
// 把當前幀畫到隱藏 canvas，只讀左上角那一小塊
ctx.drawImage(video, 0, 0);
const px = ctx.getImageData(0, 0, 324, 14).data;
// 依 SYNC 樣式決定閾值，逐格判定，驗 CRC
```

成本極低 —— 只讀 324×14 像素，不是整張畫面。
